# Warm execution of the seed-42 babashka/fs workload

The combined workload fell from **1,032.9 to 165.5 ms per 100 passes** after changing the Chez host's `java.io.File` dispatch. The fixed Jolt used 24% less time than Babashka (217.3 ms) and 1.92× the time of JVM Clojure (86.2 ms). All three returned `580311`.

## Where the time went

Times below are ns per call, before → after. The probe mirrored the five forms in `features.bb` and cycled through 1,024 distinct input pairs. For index `i`, it used `x = (4871i + 42) mod 1000003` and `salt = 1 + (71i mod 887)`. Each timing is the median of five batches of 32,768 calls after one warmup batch.

The build probe constructed the input string and consumed its length. The fs probe operated on prebuilt strings and consumed the result length, including the return-value `str` where the generator uses it. The fold probe ran the generator's `text-code` on precomputed output strings. Each loop accumulated its results. A control that only fetched and counted a string took 17–18 ns per call.

| Operation | Build | fs call | Fold | Full form |
| --- | ---: | ---: | ---: | ---: |
| `file-name` | 152 → 155 | 5,546 → 193 | 300 → 305 | 6,491 → 639 |
| `parent` | 150 → 156 | 6,142 → 433 | 276 → 281 | 6,655 → 839 |
| `extension` | 152 → 158 | 6,170 → 585 | 297 → 309 | 6,710 → 1,047 |
| `strip-ext` | 149 → 155 | 5,978 → 550 | 299 → 296 | 6,697 → 992 |
| `normalize` | 154 → 154 | 6,047 → 465 | 227 → 233 | 6,854 → 880 |

The vendored `file-name` calls `File.getName` through `as-file`. Both extension operations reach it through `split-ext`. For a string, `parent` and `normalize` use `as-path`, which calls `File.toPath` before the corresponding NIO Path method. On prebuilt receivers, `File.getName` took 5,494 ns, `File.toPath` took 5,678 ns, and `Path.getParent` took 136 ns. [Vendored fs](../../../vendor/fs/src/babashka/fs.cljc) · [NIO Path implementation](../../../host/chez/java/nio-file.ss)

The File dispatcher eagerly called `jfile-fs` for each method. On a relative path, `project-relative` consulted `jolt-user-dir`, which calls Chez's `current-directory` when `JOLT_PWD` is unset. Reading `user.dir` alone took 5,354 ns. In a separate control, baseline `File.getName` took 5,870 ns on relative paths, 128 ns on absolute paths, and 286 ns on the same relative paths with `JOLT_PWD` set.

Lexical File methods now use the stored pathname. Methods needing a resolved path enter a separate dispatch function. `File.toPath` passes the pathname to the NIO constructor for validation, including NUL rejection. With the fix, `File.getName` took 126 ns, `File.toPath` took 141 ns, and `Path.getParent` took 138 ns. [File implementation](../../../host/chez/java/io.ss)

## Measurement conditions

Both release binaries were built with `make jolt-release` from checkout `e5485016` on an Apple M3 Ultra VM running arm64 macOS 15.7.3 and Chez 10.4.1. The baseline reported `v0.8.25-109-ge54850168`. Babashka was 1.12.218 and JVM Clojure was 1.12.4 on OpenJDK 25.0.2. The absolute checkout `target/release` directory came first on `PATH`, and `command -v jolt` was checked for both sweeps.

Each project was generated once with seed 42, 5k target lines and 400 lines per namespace. Both builds ran the same generated files and independent oracle with input 42. The runner launched one runtime at a time. All 1,872 executions matched their oracle, including warmups and the extra cache-populating launch per build, profile and runtime. Launch 0 in the CSV is the first launch. [Per-launch load and execution samples](2026-11-10-seed42-fs-samples.csv)

## Path semantics and tests

Both Jolt builds, Babashka and JVM Clojure agreed on the five operations for strings, Files and Paths, including empty paths, roots, repeated separators, dot segments, dotfiles and compound extensions. They also agreed on URI normalization and NUL rejection by `File.toPath`.

The fs, path-normalization, canonical-path, platform-path, working-directory and benchmark-kit tests passed. The added regression check counts `user.dir` lookups during relative `File.getName` and `File.toPath` calls. It failed against the baseline dispatcher and passed against the fix. [Regression check](../../../test/chez/win-path-test.ss)
