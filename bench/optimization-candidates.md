# Jolt optimization candidates from production Clojure

**I’d prototype one-descent `update` first.** Metabase counts graph edges with the exact operation, and Jolt’s current implementation exposes both traversals in one line. **For a compiler pass, I’d start with fixed-field loop accumulators.** Metabase and clj-kondo supply two different workloads with a locally visible proof. The automatic transient builder also has direct matches in two projects, plus a compatibility issue worth testing before measuring it.

## 1. Use a transient builder for an unobserved map accumulator

The original proposal, written with the three-argument map reducer, is `(reduce-kv (fn [acc k v] (assoc acc k v)) {} m)`. An internal mutable builder can accumulate entries and produce the persistent result once. The important proof concerns **every intermediate version**. A reducer can publish an old accumulator, and a custom `IKVReduce` source can observe the seed or step results.

**Pedestal** does this on the HTTP-kit request path. It normalizes newlines in each header value, associates the result into a map seeded with `{}`, then passes the completed request to its interceptors. **HoneySQL** does the key-transforming variant when normalizing named SQL parameters. These give two useful inputs for measurement, string-keyed headers and parameters normalized to keywords. [Pedestal request handler](https://github.com/pedestal/pedestal/blob/07b7a2e945dd648480732c8b862511f87c787247/http-kit/src/io/pedestal/http/http_kit.clj#L113-L135) · [HoneySQL parameter normalization](https://github.com/seancorfield/honeysql/blob/d0e12041b8acdff8ca91ecfc4a1f39ccfacf1c00/src/honey/sql.cljc#L2598-L2609)

**A verified Jolt constraint.** On this checkout, inserting nine distinct keyword keys into `{}` with `assoc` produced a `PersistentArrayMap`. Building the same entries with `assoc!` and `persistent!` produced an equal `PersistentHashMap` with a different key iteration order. A compiler-generated builder needs the persistent promotion rule wherever the result’s representation is observable. Keep the original seed on an empty traversal and specialize trusted reduction implementations. [Persistent promotion thresholds](../host/chez/collections.ss#L1197-L1207) · [Transient buffer allocation](../host/chez/transients.ss#L66-L77) · [Transient promotion](../host/chez/transients.ss#L178-L191)

## 2. Carry fixed accumulator fields as loop locals

**Metabase** checks password complexity by carrying a literal map of six character-class counters through a loop. Each character increments two or three statically named fields. Only at loop exit does a caller look up fields by a runtime key. Six locals and one final map preserve that interface. **clj-kondo** carries two vectors, `:new-children` and `:schemas`, through its schema-removal loop. The caller immediately destructures the loop result, so even the final *accumulator* map could disappear. The vectors themselves remain live. [Metabase counter loop and consumer](https://github.com/metabase/metabase/blob/3763e9ccd9672b0bdc166c4c358bc72317288996/src/metabase/util/password.clj#L12-L55) · [clj-kondo schema analysis](https://github.com/clj-kondo/clj-kondo/blob/a38978c2fe24b3790b2b7a6d3007594c087dd863/src/clj_kondo/impl/schema.clj#L8-L29)

Start with `loop/recur`, where all uses of the accumulator are visible. **Penpot** supplies the follow-up `reduce-kv` case. Its per-page shape counter carries a total and a by-type map, skips the synthetic root, and feeds file statistics. That extension needs proof about the reduction implementation as well as the callback. [Penpot reducer and aggregation](https://github.com/penpot/penpot/blob/fd785b8246d41e399911a36cfd0f2d53c0500a8f/common/src/app/common/files/stats.cljc#L17-L54) · [Backend consumer](https://github.com/penpot/penpot/blob/fd785b8246d41e399911a36cfd0f2d53c0500a8f/backend/src/app/rpc/commands/files.clj#L707-L717) · [Jolt’s existing scalar-replacement pass](../jolt-core/jolt/passes/inline.clj#L632-L640)

## 3. Perform the lookup and write in `update` with one descent

**Metabase’s join-pruning code** starts a degree table at `{}` and executes `(update %1 %2 (fnil inc 0))` for each eligible edge endpoint. It reads the counts to decide which joins it can remove. A loop edge deliberately contributes twice. **Penpot** uses the same update to count shapes by type. These are variable-key workloads, so fixed-field scalar replacement cannot eliminate these lookups. [Metabase degree accumulation](https://github.com/metabase/metabase/blob/3763e9ccd9672b0bdc166c4c358bc72317288996/src/metabase/parameters/chain_filter/dedupe_joins.clj#L18-L28) · [Join pruning](https://github.com/metabase/metabase/blob/3763e9ccd9672b0bdc166c4c358bc72317288996/src/metabase/parameters/chain_filter/dedupe_joins.clj#L109-L118) · [Penpot shape-type count](https://github.com/penpot/penpot/blob/fd785b8246d41e399911a36cfd0f2d53c0500a8f/common/src/app/common/files/stats.cljc#L17-L39)

Jolt implements `update` as `get`, a call to the updater, and `assoc`. A built-in map could retain the matching slot or trie path, call the updater once, and rebuild from there. The old map can remain live. Benchmark insertion and replacement separately, with both array and hash maps. Preserve missing-key, stored-key, metadata, and unchanged-value behavior. Built-in keys make a good first scope because user-defined hashing and equality can observe calls. [Jolt’s update](../jolt-core/clojure/core/00-kernel.clj#L72) · [Persistent map association](../host/chez/collections.ss#L1301-L1317)

## 4. Combine nested edits that share a path

**Penpot’s graph sync** moves a shape by making four consecutive `assoc-in` edits under `[:shapes shape-id]`, with a fifth when a page ID is present. The compiler could find the shape once, apply the edits in order, and rebuild the common ancestors once. The old-parent lookup before the edits must still see the old shape. This is an especially good benchmark because the common prefix and all four mandatory edits occur together in one function. [Penpot shape move](https://github.com/penpot/penpot/blob/fd785b8246d41e399911a36cfd0f2d53c0500a8f/backend/src/app/graph/sync.clj#L304-L314)

**clj-kondo** registers a namespace alias with two `assoc-in` calls sharing three dynamic keys, `[base-lang lang ns-sym]`. The change belongs inside the existing `swap!` callback so each retry works from the current namespace map. Both workloads use local values in the shared prefix, avoiding any need to speculate about repeated key expressions with side effects. [clj-kondo alias registration](https://github.com/clj-kondo/clj-kondo/blob/a38978c2fe24b3790b2b7a6d3007594c087dd863/src/clj_kondo/impl/namespace.clj#L393-L399)

## 5. Return multiple Scheme values to callers that immediately destructure

**XTDB** has almost exactly the motivating parser pattern. Its private quoted-identifier scanner returns a vector containing the parsed string and the position after the closing quote. The caller destructures it inside the parsing loop and casts the position back to `long`. A direct entry point returning two Scheme values could eliminate one vector per quoted component. The scanner still throws on an unterminated identifier, and its ordinary callable entry point must honor the vector return contract. [XTDB scanner and caller](https://github.com/xtdb/xtdb/blob/2dea05644a4b95359d4d2707060f20c3130ed693/core/src/main/clojure/xtdb/expression.clj#L1676-L1723)

**Metabase’s JSON middleware** gives a second case with different control flow. Its private helper returns a boolean and either the request or a parse exception. Both the synchronous and asynchronous handlers immediately destructure that pair, including on requests whose bodies need no decoding. [Metabase helper and both callers](https://github.com/metabase/metabase/blob/3763e9ccd9672b0bdc166c4c358bc72317288996/src/metabase/server/middleware/json.clj#L93-L129)

## 6. Count groups without building their member vectors

**Metabase** groups Quartz trigger keys by state and immediately converts each bucket to a count for Prometheus. The trigger-completion listener invokes this function. One counter per observed state eliminates retention of all the trigger keys in bucket vectors. The state selector calls the scheduler, so the rewrite must preserve the number and order of those calls. **Pedestal** groups routes by name, counts each bucket, and reports duplicate names. That is route-construction work, and the diagnostic exposes the order of the reported names. [Metabase metrics and listener](https://github.com/metabase/metabase/blob/3763e9ccd9672b0bdc166c4c358bc72317288996/src/metabase/analytics/quartz.clj#L46-L86) · [Pedestal route validation](https://github.com/pedestal/pedestal/blob/07b7a2e945dd648480732c8b862511f87c787247/route/src/io/pedestal/http/route/definition.clj#L48-L58)

The original sketch used `(update-vals (group-by f xs) count)`. Both projects spell the consumer as a function over `[key bucket]` entries. A pass that recognizes only the original spelling would miss both. Jolt already uses transient buckets in `group-by`. Eliminating them requires seeing what consumes each bucket. [Jolt’s group-by](../jolt-core/clojure/core/20-coll.clj#L108-L135)

## 7. Fuse an explicit transducer pipeline into its driving loop

**HoneySQL** checks row widths while formatting SQL `VALUES`. On the relevant branch it has already converted the input to a vector, possibly a subvector. It evaluates `(into [] (comp (filter sequential?) (map count)) xs)`. Transducers already make this one pass. The opportunity is to walk vector leaves and execute the predicate, count, and output append directly. The measurement is the incremental gain over normal transduction, including for ragged inputs where the caller uses the collected widths. [HoneySQL formatter](https://github.com/seancorfield/honeysql/blob/d0e12041b8acdff8ca91ecfc4a1f39ccfacf1c00/src/honey/sql.cljc#L1419-L1442)

**Metabase’s BigQuery driver** maps row parsers and optionally applies `take` to a host iterable. It illustrates the next boundary. A vector-only pass should fall back here. A later iterable specialization would also have to preserve early termination and the number of rows parsed. [Metabase row decoding](https://github.com/metabase/metabase/blob/3763e9ccd9672b0bdc166c4c358bc72317288996/modules/drivers/bigquery-cloud-sdk/src/metabase/driver/bigquery_cloud_sdk.clj#L1428-L1443)

## 8. Share a layout among escaping ordinary keyword maps

**Ring** constructs an ordinary 14-key map for a Jakarta servlet request. Jetty passes it to an arbitrary configured handler, so the allocation escapes. Ring’s static-resource middleware reads `:request-method` and calls a helper that looks for `:path-info` and falls back to `:uri`. This gives a producer, an escape, a successful lookup, and a missing-key lookup in real code. [Request-map construction](https://github.com/ring-clojure/ring/blob/5f745bbc7daefa097d7e9cf6394b44dce51cf597/ring-jakarta-servlet/src/ring/util/jakarta/servlet.clj#L30-L46) · [Jetty handler handoff](https://github.com/ring-clojure/ring/blob/5f745bbc7daefa097d7e9cf6394b44dce51cf597/ring-jetty-adapter/src/ring/adapter/jetty.clj#L111-L122) · [Resource middleware](https://github.com/ring-clojure/ring/blob/5f745bbc7daefa097d7e9cf6394b44dce51cf597/ring-core/src/ring/middleware/resource.clj#L9-L29) · [Path lookup](https://github.com/ring-clojure/ring/blob/5f745bbc7daefa097d7e9cf6394b44dce51cf597/ring-core/src/ring/util/request.clj#L64-L69)

A shared descriptor could store the key layout once and let guarded literal-key reads load a value by slot. Middleware can add fields or replace the request, so measure original and extended maps and record how often the guard succeeds. The representation must preserve ordinary map behavior, including the iteration order Jolt exposes for the corresponding literal.

The Ring experiment supports keeping the current implementation. Across four alternating trials at each of two sizes using the same patched Chez 10.4.1, splitting the 14-key literal's slots cut constructor allocation from 288 to 176 B and saved about 2.8–3.0 ns per construction. With that same backing, the descriptor guard cut a repeated `:path-info` miss from about 18 to 11.5 ns. Warm hits were already about 10 ns in the current runtime and took about 11.5 ns with the prototype. The guard hit on every warmed probe of an original request, on 25% of the method probes in the mixed receiver control, and on none after adding or removing a key. The adapted resource-hit path stayed around 24 μs per request with about 1% less allocation, while either key edit added 128 B per request. The exact prototype, Chez patches and build settings, fixture, emitted code, counts and alternating samples are in `refs/benchmarks/jolt-33`.

## 9. Skip shared trie subtrees in set difference

**Specter** provides a conditional match with a traceable origin for both operands. Its `subset` navigator computes an intersection, transforms that subset, and subtracts the original subset from the input before unioning the replacement. Take two persistent hash sets of keywords. When the input is smaller or ties, Jolt’s intersection starts with that input and removes rejected members. The subsequent difference therefore receives the original set and either itself or a descendant. With a sparse edit, a trie-aware difference could skip identical subtrees. If the other operand is smaller, this ancestry argument falls away. [Specter navigator](https://github.com/redplanetlabs/specter/blob/6119462a4d959834f2d78a6183d74608bf08ab52/src/clj/com/rpl/specter.cljc#L887-L900) · [Jolt intersection and difference](../stdlib/clojure/set.clj#L33-L53)

**Logseq** supplies a concrete application case in ClojureScript. Its graph importer seeds a visited set with PDF annotation parent IDs, grows it by union with newly discovered IDs, then subtracts the original parents to get just the descendants. When each new frontier is no larger than the visited set, union extends the visited set throughout and the final operands have common ancestry. The importer also shows why to profile first. Finding each frontier already scans the blocks. [Logseq traversal](https://github.com/logseq/logseq/blob/8ab397fef8b8c8804554a72e9e9d9768dc1317bc/deps/graph-parser/src/logseq/graph_parser/exporter.cljs#L1607-L1621) · [Importer call with highlight IDs](https://github.com/logseq/logseq/blob/8ab397fef8b8c8804554a72e9e9d9768dc1317bc/deps/graph-parser/src/logseq/graph_parser/exporter.cljs#L1675-L1682) · [ClojureScript union](https://github.com/clojure/clojurescript/blob/f43d3c81a77f4d417323837518d21521e4d26189/src/main/cljs/clojure/set.cljs#L19-L26)

**Onyx** is a useful control. Its messaging subscriber computes both directions of an old/new peer-ID difference, but constructs the two sets independently. Old/new names and high value overlap alone do not establish shared nodes. Before proposing a PR, measure the fraction of identical trie children on the Specter path and the cost of the same checks on independently built sets. [Onyx peer update](https://github.com/onyx-platform/onyx/blob/dfcd1965ffa1c03813d2a4cc785dc78bfe5485a0/src/onyx/messaging/aeron/subscriber.clj#L219-L237)

## What would justify a PR

Use the upstream function or public entry point, compare the same workload on the same Jolt revision with the optimization enabled and disabled, and record allocated bytes and elapsed time. Inspect the emitted code or count primitive calls to confirm the intended work disappeared. Include typical small inputs. A header map or password can be small enough that setup costs decide the outcome.

HoneySQL offers a particularly short path from source evidence to a measurement. Jolt already has a workload invoking upstream `sql/format` with named parameters. Its pinned HoneySQL version contains both the parameter reducer and the row-width pipeline. The existing driver exercises parameters. Add a multi-row `VALUES` call to exercise the pipeline. This survey establishes occurrences in shipped code. Call frequency, input distributions, and speedups remain to be measured. [Jolt workload](../ci/pgo-workloads/honeysql/src/pgo_honeysql.clj#L32-L35) · [Pinned dependency](../ci/pgo-workloads/honeysql/deps.edn#L3-L5) · [Parameter reducer at that pin](https://github.com/seancorfield/honeysql/blob/308d5a741825cb13ded6d4766041306a61181acb/src/honey/sql.cljc#L2537-L2540) · [Row-width pipeline at that pin](https://github.com/seancorfield/honeysql/blob/308d5a741825cb13ded6d4766041306a61181acb/src/honey/sql.cljc#L1356-L1374)
